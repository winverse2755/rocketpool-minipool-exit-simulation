# Reproducing the published experiment

Start with the environment setup in [README.md](../README.md). Installation needs
internet access; all commands below use the checked-in files offline. The tested
setup is CPython 3.14 on macOS arm64. [requirements.txt](../requirements.txt) pins the
direct dependencies; [requirements-lock.txt](../requirements-lock.txt) also pins
the transitive packages from that tested environment. Other platforms are not
verified by this cleanup.

## 1. Check the published files before running anything

```sh
python scripts/check_artifacts.py
```

This compares each file listed in [sha256_manifest.json](../results/sha256_manifest.json)
with its SHA-256 digest and exits nonzero for missing or changed files. It checks
integrity against the included record, not authenticity or scientific validity.
The manifest excludes itself and the maintenance handoff in [PLAN.md](PLAN.md).

Run it before regeneration: charts and spreadsheets can contain timestamps or
platform-dependent rendering, so a valid rerun need not match every artifact byte.

## 2. Run the simulation and numerical checks

```sh
python scripts/simulate.py
python scripts/verify.py
python scripts/check_artifacts.py --rerun
```

Keep the default parameters to reproduce the published experiment:

| Parameter | Default |
| --- | --- |
| `--seed` | `20261007` |
| `--alternate-seed` | `20261008` |
| `--draws` | `1000` |
| `--pointers` | `20` |
| `--demands` | `50000 10000 200000` |

The script evaluates strict-cap and include-first-crossing rules. The latter is
only a sensitivity check. Run `python scripts/simulate.py --help` to inspect the options.
Custom parameters are experiments, not reproductions: the report contains
published-scenario prose, and downstream checks expect the 50,000-rETH scenario.

The seven deterministic CSVs compared by `--rerun` are `draws.csv`, `summary.csv`,
`robustness.csv`, `overshoot_deltas.csv`, `sweep_pointers.csv`,
`representative_prefixes.csv`, and `representative_nodes.csv`. Their expected
hashes come from [reproducibility.json](../results/reproducibility.json). This command checks
the files currently on disk; run the simulation first to establish fresh evidence.
Do not replace the expected hashes just to make a mismatch pass.

For the validator-index 50k strict-cap case, expect:

| Quantity | Expected value |
| --- | ---: |
| Selected validators | 2,995 |
| Credited user capital | 58,528 ETH |
| Nodes touched | 598 |
| Eligible minipool books wiped | 206 |
| Exits on wiped nodes | 12.1202% |
| Top-10 node share | 41.7028% |

`verify.py` uses assertions and writes [verification.json](../results/verification.json).
Never use `python -O` or set `PYTHONOPTIMIZE` for these checks.

## 3. Rebuild the report and figures

```sh
python scripts/build_report.py
python scripts/make_post_figures.py
python scripts/make_size_comparison.py
```

Run all commands from the repository root. The report builder writes [REPORT.md](../reports/REPORT.md), calls `post_metrics.py` to
regenerate the additional post data, and calls `build_post.py` to check that the
editorially maintained [POST.md](../reports/POST.md) exists. It does not rewrite the README
or the post. Plot scripts rebuild the publication PNGs and size-comparison
CSV/PDF/SVG. The saved forum ZIP is not regenerated by these commands.

## 4. Optional spreadsheet recalculation

`simulate.py` writes formulas and cached Python values to `hand_check.xlsx`.
Reading those caches is not independent spreadsheet evaluation. The repository
also contains a workbook previously recalculated in Apple Numbers; `verify.py`
checks its saved values against the current numerical reconciliation when present.
That does not mean Numbers was launched during your run.

For a fresh application recalculation on macOS with Numbers installed:

```sh
osascript scripts/recalculate.applescript "$PWD/results/hand_check.xlsx" "$PWD/results/hand_check_recalculated.xlsx"
python scripts/verify.py
python scripts/build_report.py
```

macOS may request automation permission. Other spreadsheet applications may be
used, but their exported sheet layout must remain compatible with `verify.py`.
Without the recalculated file, numerical checks still run and the verification
record explicitly reports the missing spreadsheet evidence.

## What is preserved, and what is regenerated?

- **Frozen inputs:** `minipools.csv`, `nodes.csv`, `snapshot.json`, saved sources,
  and the original clustering results. Collection provenance is in
  [provenance.md](provenance.md); upstream collection is outside this repository.
- **Generated:** simulation CSVs/JSON, charts, `hand_check.xlsx`, post metrics,
  and `REPORT.md`. Running the pipeline overwrites these in their respective folders.
- **Maintained or saved:** `README.md`, this guide, `POST.md`, provenance,
  the forum bundle, the recalculated workbook, and expected hash records.

For a reproducibility report, record the Git commit, OS/architecture,
`python --version`, installed package versions, command exit codes, and the
seven-CSV comparison result. A hash mismatch is a failure to reproduce bytes;
it is not by itself proof that the scientific conclusions changed.
